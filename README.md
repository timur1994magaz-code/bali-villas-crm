# 🌴 Bali Villas CRM — управление субарендой вилл

Управленческая CRM для бизнеса субаренды вилл на Бали: виллы, контакты, условия аренды, цены и маржа, фотогалерея, Google-точка, календарь занятости с зумом (день / неделя / месяц / год) и клиенты с документами.

Работает как обычный сайт — без сервера, без установки, без регистрации. Все данные и файлы хранятся локально в браузере (IndexedDB).

## Что внутри

| Раздел | Что делает |
|---|---|
| **Дашборд** | Занятость месяца, выручка, платежи собственникам, маржа, заезды/выезды на 14 дней, остатки к оплате, свободные виллы |
| **Виллы** | Список карточками или таблицей: название, район, контакты, условия, цена собственника, наша цена, маржа |
| **Карточка виллы** | Вкладки: Обзор · Фото · Локация · Календарь · Брони · Документы |
| **Календарь** | Таймлайн «виллы × дни» как в Airbnb: зум День / Неделя / Месяц / Год, протяжка мышью для создания брони |
| **Клиенты** | Контакты, история проживаний, финансы, файлы (договор, паспорт, виза) |
| **Настройки** | Валюта, бэкап/восстановление, демо-данные, объём хранилища |

### 1–4. Виллы, контакты, условия, цены
Для каждой виллы: название, район, адрес, спальни/санузлы, бассейн, Wi-Fi; контакты собственника (телефон, WhatsApp, e-mail), менеджера/хаускипера, телефон и e-mail виллы, Instagram; условия аренды (срок договора, порядок оплаты, депозит, уведомление о расторжении, коммунальные, условия текстом); **цена собственника** (за ночь / в месяц / в год) и **наша цена** (за ночь и в месяц) — маржа в деньгах и процентах считается автоматически.

### 5. Фото в хорошем качестве
Вкладка «Фото» в карточке виллы: перетащите файлы или выберите. Клик открывает полноэкранный просмотр
(стрелки ← →), есть подписи, кнопка «★» назначает обложку, скачивание оригинала и «Скачать все».

Как хранить снимки, решает общая настройка «Настройки» → «Качество хранения фото»:

* **Оригинал** — файл сохраняется как есть, без сжатия;
* **до 2560 px** или **до 1920 px** — снимок уменьшается прямо в браузере перед отправкой,
  занимает в 4–6 раз меньше места, на экране разницы не видно. Файл на вашем компьютере не меняется.

Настройка общая для всех сотрудников, действует только на новые загрузки.
Полные оригиналы удобно держать на Google Диске: в карточке виллы есть поле для ссылки на папку,
а на вкладке «Фото» появляется кнопка «Открыть папку».

### 6. Локация с Google-точкой
Вставьте ссылку Google Maps или координаты — кнопка «Достать координаты из ссылки» распознаёт формат `.../@-8.6595,115.1379,17z`, `?q=lat,lng`, `!3d…!4d…` или просто `-8.6595, 115.1379`. Карта показывается прямо в карточке, есть кнопки «Открыть в Google Maps» и «Маршрут».

> Короткие ссылки `maps.app.goo.gl` координат не содержат: откройте такую ссылку в браузере и скопируйте адрес из строки, либо вставьте координаты вручную.

### 7. Календарь занятости
Общий таймлайн: строки — виллы, колонки — дни, цветные полосы — брони. Четыре масштаба:

* **День** — 3 дня, максимальное приближение
* **Неделя** — 7 дней
* **Месяц** — месяц целиком (по умолчанию)
* **Год** — все 12 месяцев с прокруткой

Протяните мышью по строке виллы — откроется форма новой брони на выбранный период. В карточке виллы есть ещё и классическая сетка на 12 месяцев вперёд, где занятые дни закрашены. Статусы: заселён, забронировано, опция (ждём оплату), блок (собственник/ремонт). Пересечение дат подсвечивается предупреждением. День выезда считается свободным для следующего заезда.

### 8. Клиенты и файлы
У клиента хранится **бюджет в месяц** — он виден отдельным столбцом в списке, а кнопка
«🔎 Подобрать виллы» в карточке сразу открывает подбор с этим бюджетом.

Клик по брони в календаре открывает карточку с контактами клиента (телефон, WhatsApp, Telegram, e-mail — кликабельные), деньгами (сумма, предоплата, остаток, цена за ночь) и двумя папками файлов: документы клиента (договор, паспорт, виза) и файлы по конкретной брони. Любые форматы: PDF, фото, сканы, Word, Excel.

## Подбор виллы под запрос клиента

Раздел «🔎 Подбор» отвечает на типовой вопрос: клиент хочет двухкомнатную с 28 ноября
на два месяца в бюджете 30 млн в месяц — что у нас есть?

Задаёте дату заезда, срок (1–12 месяцев или своя дата выезда), число спален, район
и бюджет в месяц. Сумму можно писать как удобно: `30 млн`, `30jt` или `30000000`.
В ответ — список подходящих вилл, отсортированный от дешёвых, с ценой за месяц,
прикидкой стоимости за весь срок и запасом до бюджета.

Про занятость честно: «свободна весь срок», «свободна с 20.12» с указанием, кем и до
какого числа занята, либо «занята весь срок». Галочка «только полностью свободные»
отсекает лишнее, а если её снять — увидите и те, что освобождаются в середине срока.
Кнопка «Забронировать» открывает бронь, подставив дату освобождения.

Все суммы в рупиях.

## Как пользоваться

1. Откройте приложение (см. ссылку в описании репозитория или запустите локально).
2. «Настройки» → «Загрузить демо-данные», чтобы посмотреть, как всё работает.
3. Когда разберётесь — «Настройки» → «Удалить всё» и заводите свои виллы.

### Локальный запуск

```bash
git clone https://github.com/<ваш-логин>/bali-villas-crm.git
cd bali-villas-crm
python3 -m http.server 8777
# откройте http://localhost:8777
```

Просто открыть `index.html` двойным кликом (`file://`) нельзя — браузер блокирует ES-модули. Нужен любой локальный сервер или GitHub Pages.

## Совместная работа с сотрудником

Приложение умеет работать в трёх режимах — переключение не требует правки кода, режим определяется сам:

| Режим | Где данные | Когда подходит |
|---|---|---|
| **Свой сервер** | На вашем VPS: база SQLite и файлы на диске | Полная независимость, объём — сколько на диске, платы нет. См. **[DEPLOY.md](DEPLOY.md)** |
| **Supabase** | В облачном проекте Supabase | Не хочется заниматься сервером. Бесплатно до 1 ГБ файлов. См. **[SETUP-SUPABASE.md](SETUP-SUPABASE.md)** |
| **Локально** | В браузере (по умолчанию) | Работа в одиночку на одном устройстве |

### Свой сервер — установка одной командой

```bash
git clone https://github.com/timur1994magaz-code/bali-villas-crm.git /opt/bali-crm
bash /opt/bali-crm/deploy/install.sh crm.вашдомен.ру ваша@почта.ру
```

Скрипт ставит Node.js, поднимает службу, настраивает nginx, получает сертификат https
и включает ночные резервные копии. Сервер написан на встроенных средствах Node.js —
**сторонних библиотек ноль**, обновлять нечего. Сотрудников заводите прямо в приложении:
«Настройки» → «Сотрудники».

### Supabase — если сервера нет


По умолчанию база живёт в браузере, поэтому у сотрудника открылась бы пустая копия.
Чтобы работать вдвоём, подключите бесплатный проект Supabase — данные, фото и документы
переедут в общее хранилище, а вход станет по почте и паролю.

Настройка занимает около 15 минут и делается один раз: **[SETUP-SUPABASE.md](SETUP-SUPABASE.md)**.
Схема базы — в [`supabase/schema.sql`](supabase/schema.sql).

Что получится:

* Сотрудников вы заводите и отключаете сами: **Authentication → Users** в панели Supabase.
* Изменения видны обоим сразу, без обновления страницы.
* Фото и документы лежат в приватном хранилище — открыть их можно только войдя в систему.
* Локальный режим никуда не делся: общую базу можно отключить в «Настройках» и вернуться к работе на одном устройстве.

Ограничения бесплатного тарифа, о которых стоит знать заранее: **1 ГБ на файлы**
(для большого фотоархива включите режим «до 2560 px») и **пауза после 7 дней без обращений**
к базе — проект снимается с паузы кнопкой в панели Supabase. Подробности — в инструкции.

## Сколько фото выдержит

Ориентир: 50 вилл × 20 фото = 1000 файлов. Фото с телефона — 3–5 МБ, то есть весь архив ≈ 3–5 ГБ. Это рабочий объём, но с оговорками:

| Браузер | Сколько даёт одному сайту |
|---|---|
| **Chrome / Edge** | около 60% свободного места на диске — при 100 ГБ свободных это ~60 ГБ. Запас огромный |
| **Firefox** | около 10% от диска на сайт |
| **Safari** | заметно меньше (порядка 1 ГБ, дальше спрашивает разрешение), плюс может очистить данные сайта, если им не пользовались ~7 дней |

**Вывод: для большого архива работайте в Chrome.** Текущий расход и остаток видно в «Настройках» → «Хранилище», там же полоса заполнения; при остатке меньше 500 МБ приложение предупредит, а если места не хватит на загрузку — скажет об этом до начала.

Чтобы интерфейс не тормозил на тысяче фото, при загрузке рядом с оригиналом сохраняется превью (~30–70 КБ). Сетки, обложки вилл и карточки рисуются превью, оригинал открывается только в полноэкранном просмотре и при скачивании. Замеры на 52 виллах и 1000 фото: список вилл со всеми обложками — 0,27 с, вкладка «Фото» с 20 снимками — 0,06 с, календарь на 52 виллы — мгновенно.

Если 3–5 ГБ в браузере смущают, в «Настройках» есть **«Качество хранения фото»**: режим «До 2560 px» уменьшает файлы в 4–6 раз (весь архив ≈ 0,8 ГБ) при том же виде на экране и на проекторе. По умолчанию стоит «Оригинал — без сжатия». Настройка влияет только на новые загрузки.

**HEIC с iPhone**: Chrome и Firefox такие файлы не показывают вовсе (это ограничение браузера, не приложения). На телефоне: Настройки → Камера → Форматы → «Наиболее совместимый» — снимки будут в JPEG. Приложение предупредит, если вы загрузите HEIC.

## Где хранятся данные

Зависит от режима. В **общей базе** (см. раздел выше) — в вашем проекте Supabase, и тогда всё
сказанное ниже про бэкап остаётся верным, но данные уже не привязаны к одному браузеру.
В **локальном режиме** (по умолчанию) — в IndexedDB того браузера, в котором вы работаете. Ничего не уходит в интернет — ни фото, ни паспорта клиентов. Отсюда два следствия:

* На другом компьютере или в другом браузере база будет пустой.
* **Бэкап — единственная защита от потери.** Не чистите «данные сайтов» без свежего бэкапа. Приложение запрашивает у браузера постоянное хранилище (`navigator.storage.persist`), чтобы данные не вытеснялись автоматически.

Три способа бэкапа в «Настройках»:

| Способ | Когда использовать |
|---|---|
| **📁 Папка на диске** (Chrome/Edge) | Основной вариант при больших архивах: пишет `data.json` и файлы прямо в выбранную папку или на внешний диск, размер не ограничен, повторный бэкап копирует только новое |
| **🗜️ ZIP** | Работает в любом браузере, сам делится на части по 1,2 ГБ. Для восстановления выберите сразу все части |
| **📄 JSON** | Только виллы, брони и клиенты, без фото — маленький файл, удобно делать хоть каждый день |

Восстановление — теми же кнопками: «Заменить» затирает текущую базу, «Отмена» дописывает данные из бэкапа к существующим.

## Технологии

Чистый JavaScript (ES-модули), IndexedDB, без сборки и зависимостей. Любой современный браузер: Chrome, Safari, Edge, Firefox. Адаптивно под телефон и планшет.

```
index.html
assets/styles.css
server/           сервер для своего VPS: Node.js + SQLite, без зависимостей
  server.js       API, статика, живое обновление, вход
  cli.js          управление сотрудниками из терминала
  lib/            хранилище и пароли
deploy/           установка на VPS: install.sh, systemd, nginx, резервные копии
supabase/
  schema.sql      таблицы, права доступа и хранилище для Supabase
js/
  app.js          роутер, вход в систему, живое обновление
  db.js           IndexedDB: виллы, брони, клиенты, файлы, превью
  store.js        данные, бизнес-логика, маржа, занятость
  data.js         единый слой данных: свой сервер, Supabase или браузер
  selfhost.js     работа со своим сервером
  cloud.js        Supabase: записи, файлы, вход, подписка на изменения
  config.js       подключение к проекту Supabase
  migrate.js      перенос локальной базы в общую
  backup.js       бэкап в папку / ZIP / JSON и восстановление
  zip.js          свой ZIP-писатель и читатель, без зависимостей
  images.js       превью и опциональное уменьшение оригинала
  util.js         даты, деньги, парсинг Google Maps
  ui.js           модалки, тосты, лайтбокс
  booking.js      форма и карточка брони
  files-ui.js     загрузка фото и документов
  views/          dashboard · villas · villa · calendar · clients · settings
```
