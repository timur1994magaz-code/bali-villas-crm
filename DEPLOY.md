# Установка на свой сервер

CRM целиком переезжает на ваш VPS: приложение, база и все фотографии с документами.
Никаких внешних сервисов, объём ограничен только диском сервера, ежемесячной платы нет.

Внутри — сервер на Node.js со встроенной базой SQLite. Сторонних библиотек нет вообще,
поэтому обновлять и чинить нечего: один файл базы и две папки с файлами.

## Что нужно

* VPS с Ubuntu 22.04/24.04 или Debian 12, доступ по SSH
* 1 ГБ памяти достаточно (сервер занимает 60–90 МБ)
* Диск с запасом под фотографии: 1000 снимков в оригинале — это 3–5 ГБ
* Домен или поддомен, у которого A-запись указывает на этот сервер (например `crm.вашдомен.ру`)

## Установка одной командой

```bash
ssh root@ваш-сервер
apt update && apt install -y git
git clone https://github.com/timur1994magaz-code/bali-villas-crm.git /opt/bali-crm
bash /opt/bali-crm/deploy/install.sh crm.вашдомен.ру ваша@почта.ру
```

Скрипт сам поставит Node.js, заведёт системного пользователя, запустит службу,
настроит nginx, получит бесплатный сертификат https и включит ежедневную резервную копию.
В конце он напечатает адрес, логин и пароль владельца — **запишите пароль, второй раз он не покажется**.

Дальше открываете `https://crm.вашдомен.ру`, входите и работаете.

## Добавить сотрудника

Прямо в приложении: **«Настройки» → «Сотрудники» → «+ Добавить сотрудника»**.
Задаёте почту и пароль, передаёте их сотруднику — он заходит по тому же адресу.
Там же меняется пароль и закрывается доступ (кнопка «Удалить»).

Из терминала то же самое:

```bash
cd /opt/bali-crm/server
sudo -u crm CRM_DATA_DIR=/var/lib/bali-crm node cli.js add manager@вашдомен.ру
sudo -u crm CRM_DATA_DIR=/var/lib/bali-crm node cli.js list
sudo -u crm CRM_DATA_DIR=/var/lib/bali-crm node cli.js password manager@вашдомен.ру
sudo -u crm CRM_DATA_DIR=/var/lib/bali-crm node cli.js delete manager@вашдомен.ру
```

## Перенести то, что уже набрано в браузере

Если виллы и фото заведены в локальном режиме, откройте CRM на **том самом компьютере и в том самом
браузере**, где они лежат, войдите и нажмите **«Настройки» → «Перенести локальную базу этого браузера на сервер»**.
Локальная копия останется на месте, ничего не пропадёт.

Второй путь — через бэкап: в локальном режиме сделать «Бэкап в ZIP», затем на сервере
«Восстановить из ZIP». Так удобно, если данные на другом компьютере.

## Обслуживание

| Задача | Команда |
|---|---|
| Как себя чувствует | `systemctl status bali-crm` |
| Живой журнал | `journalctl -u bali-crm -f` |
| Перезапустить | `systemctl restart bali-crm` |
| Обновить до свежей версии | `sudo /opt/bali-crm/deploy/update.sh` |
| Копия прямо сейчас | `sudo /opt/bali-crm/deploy/backup.sh` |

**Резервные копии** делаются каждую ночь в 3:00 в `/var/backups/bali-crm`, хранятся 14 последних.
База копируется штатным механизмом SQLite, поэтому копия остаётся целой, даже если в этот момент
кто-то сохраняет бронь. Копии лежат на том же сервере — раз в месяц скачивайте свежую к себе:

```bash
scp root@ваш-сервер:/var/backups/bali-crm/bali-crm-*.tar.gz ~/Downloads/
```

Восстановление из такой копии:

```bash
systemctl stop bali-crm
tar xzf bali-crm-2026-08-29_0300.tar.gz -C /var/lib/bali-crm
mv /var/lib/bali-crm/crm-2026-08-29_0300.db /var/lib/bali-crm/crm.db
chown -R crm:crm /var/lib/bali-crm
systemctl start bali-crm
```

## Где что лежит

```
/opt/bali-crm          приложение и сервер
/var/lib/bali-crm      данные: crm.db, files/ (оригиналы), thumbs/ (превью)
/var/backups/bali-crm  ночные копии
/etc/systemd/system/bali-crm.service
/etc/nginx/sites-available/bali-crm
```

## Настройки службы

Меняются в `/etc/systemd/system/bali-crm.service`, после правки — `systemctl daemon-reload && systemctl restart bali-crm`.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `CRM_PORT` | 8080 | порт, который слушает сервер (наружу смотрит nginx) |
| `CRM_HOST` | 127.0.0.1 | только локальные подключения — снаружи через nginx |
| `CRM_DATA_DIR` | /var/lib/bali-crm | база и файлы |
| `CRM_APP_DIR` | /opt/bali-crm | сам сайт |
| `CRM_MAX_UPLOAD` | 512 | предел одного файла, МБ |
| `CRM_SECURE_COOKIES` | 1 | cookie входа только по https |

## Как устроена защита

* Пароли хранятся в виде scrypt-хэша с солью — восстановить их из базы нельзя.
* Вход — cookie с флагом HttpOnly, срок 30 дней; JavaScript до неё не дотягивается.
* Ни один запрос к данным не проходит без входа, включая сами фотографии и сканы паспортов:
  ссылка вида `/f/xxxx` без вашей сессии отдаёт 401.
* Запросы с чужих сайтов отсекаются обязательным заголовком, который нельзя подделать из браузера.
* Не больше 10 попыток входа за 15 минут с одного адреса.
* Управлять сотрудниками и стирать базу может только владелец.
* Служба работает под отдельным пользователем без прав, и ей доступен только каталог с данными.

Что стоит сделать самим на сервере: включить firewall (`ufw allow OpenSSH; ufw allow 'Nginx Full'; ufw enable`)
и запретить вход по SSH с паролем, оставив ключи.

## Если что-то не так

**Сайт не открывается.** `systemctl status bali-crm` — работает ли служба; `journalctl -u bali-crm -n 50` — что в журнале.

**Сертификат не выдался.** Проверьте A-запись домена: `dig +short crm.вашдомен.ру` должен вернуть IP сервера. Затем `certbot --nginx -d crm.вашдомен.ру`.

**Фото не загружается, ошибка 413.** Файл больше предела nginx — поднимите `client_max_body_size` в `/etc/nginx/sites-available/bali-crm` и `CRM_MAX_UPLOAD` в службе.

**Изменения не видны второму сотруднику сразу.** Это поток событий `/api/events` — убедитесь, что в конфиге nginx для него стоит `proxy_buffering off`.

**Забыли пароль владельца.** `cd /opt/bali-crm/server && sudo -u crm CRM_DATA_DIR=/var/lib/bali-crm node cli.js password ваша@почта.ру`
